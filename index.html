01 — GETTING STARTED

Installation

Start a new Green application with Composer. The skeleton includes a ready-to-run web app, environment configuration, migrations, and tests.

Requirements

PHP 8.3 or newer, Composer 2, and the PHP extensions required by your selected database driver.

Create the project

composer create-project yasser-elgammal/green my-app
cd my-app
cp .env.example .env
php green serve

Open http://localhost:8000. Green’s front controller captures the request, boots configured providers, dispatches the route, and sends the response.

02 — FIRST STEPS

Your first route

Routes are PHP attributes attached directly to controller methods. Return an array for JSON, a string, or a response object.

<?php

namespace App\Controllers;

use YasserElgammal\Green\Http\Request;
use YasserElgammal\Green\Routing\Route;

final class HelloController
{
    #[Route('GET', '/hello/{name}', name: 'hello')]
    public function show(Request $request, string $name): array
    {
        return ['message' => "Hello, {$name}!"];
    }
}

Register the controller with the router at your application boundary. Green reflects on the action signature and injects the current request and route parameters.

03 — HTTP

Routing

Named routes, ordered middleware, dynamic parameters, and policy attributes remain visible where behavior is defined.

#[Route(
    'PUT',
    '/users/{id}',
    middleware: [AuthMiddleware::class, AuditMiddleware::class],
    name: 'users.update'
)]
#[PolicyAttribute('update', 'id')]
public function update(Request $request, int $id): array
{
    return ['updated' => $id];
}

Generate URLs

Use route('users.update', ['id' => 42]). Extra values become query parameters.

Redirect

Return redirect('/login') to produce a redirect response.

04 — HTTP

Requests & responses

The current Request is available through dependency injection. Controller output is normalized into a concrete response—arrays become JSON responses automatically.

public function store(Request $request): Response
{
    $title = $request->input('title');

    return response()
        ->json(['created' => true, 'title' => $title], 201);
}
05 — DATA

Database

Green separates state from persistence. Model is a pure data object; Table owns queries, hydration, relations, and writes.

ModelState + dirty tracking
→
Table GatewayPersistence + relations
→
Doctrine DBALQueries + connections
$users = $userTable
    ->include('posts')
    ->query()
    ->where('status', 'active')
    ->whereGroup(fn ($query) => $query
        ->where('role', 'admin')
        ->orWhere('score', '>=', 90)
    )
    ->latest()
    ->paginate(perPage: 15, page: 1);

Relations support hasOne, hasMany, belongsTo, many-to-many, and polymorphic loading. Eager loading batches related records to prevent N+1 queries.

06 — API LAYER

Transformers & pagination

Transformers define the public JSON shape of models and automatically transform relations eager-loaded with include().

final class PostTransformer extends Transformer
{
    public function transform(Model $model): array
    {
        return ['id' => $model->id, 'title' => $model->title];
    }

    protected function includes(): array
    {
        return ['author' => new UserTransformer()];
    }
}

Unified pagination

Query pagination retains filters and ordering; Table::paginate() is the full-table shortcut. Both return data and meta.

$results = $posts->query()
    ->where('status', 'published')
    ->latest()
    ->paginate(perPage: 15, page: 1, withCount: false);
Skip expensive counts

With withCount: false, Green fetches one extra row to determine has_next; total fields are null.

07 — RELATIONS

Include Query Language

IQL constrains eager-loaded relations with one compact string: nested relations, selection, filtering, ordering, limits, offsets, and batch aggregations.

$table->include(
    'comments(limit:10,order:created_at|desc).author(select:id|name),roles'
);

$table->include('likes(exists),orders(sum:price)');
OperationExampleResult
limit / offsetlimit:5,offset:10Window related rows
orderorder:created_at|descOrder by a column
selectselect:id|nameLoad selected columns
filterfilter:status=activeFilter related rows
aggregatescount, exists, sum:priceAttach computed attributes

Aggregation-only includes skip relation hydration and run optimized batch queries.

08 — INPUT

Validation

Define input contracts as typed Payload classes. When a payload is injected into a controller, Green validates and hydrates it before your action runs.

final class CreatePostPayload extends Payload
{
    public string $title;
    public ?string $body = null;

    public function rules(): array
    {
        return [
            'title' => ['required', 'string', 'max:120'],
            'body' => ['nullable', 'string'],
        ];
    }
}
07 — PRESENTATION

Views & Twig

Green integrates Twig with named routes, translation, CSRF, and route-state helpers. View paths, cache behavior, and debug mode come from typed configuration.

<form method="post" action="{{ route('posts.store') }}">
  {{ csrf_field() }}
  <input name="title" required>
  <button>Publish</button>
</form>
08 — SECURITY

Authentication

Authentication resolves one identity for one request. Web requests use sessions by default; JWT support is an optional Composer adapter.

Request→Authenticator→Identity→Controller
#[Route('GET', '/profile', middleware: [SessionAuthMiddleware::class])]
public function show(Request $request): mixed
{
    return $request->user();
}

auth()->check(); // Is an identity resolved?
auth()->id();    // The identity's primary key
auth()->user();  // The resolved identity
Authentication ≠ authorization

Authentication answers who is making the request. Authorization asks whether that identity may perform an action. Failed authentication returns 401; failed authorization returns 403.

09 — SECURITY

Authorization

Register a policy for a resource, then check or enforce abilities through the container-owned Authorizer.

authorizer()->policy(User::class, UserPolicy::class);

authorizer()->check('update', $user, $currentUser);     // bool
authorizer()->authorize('update', $user, $currentUser); // or 403
10 — SECURITY

Sessions, hashing & CSRF

Session state

The container-managed session starts lazily and supports persistent values, one-request flash data, ID regeneration, and invalidation.

session()->set('key', 'value');
$value = session()->get('key');
session()->flash('message', 'Saved!');

$hasher = new PasswordHasher();
$hash = $hasher->hash('secret'); // bcrypt by default

CSRF protection

CSRF protection is enabled by default for POST, PUT, PATCH, and DELETE. Tokens are session-backed, time-limited, and single-use.

<form method="POST" action="/posts">
  {{ csrf_field() }}
  <input name="title">
  <button>Save</button>
</form>

{# For AJAX, call once and retain both values. #}
{% set csrf = csrf_token() %}
One token pair per request

Each csrf_token() call creates a new pair. Store it and send both values through the configured inputs or X-CSRF-ID / X-CSRF-TOKEN headers.

11 — BACKGROUND WORK

Queues

Jobs explicitly implement JobInterface. Use the synchronous driver while developing or the database driver with a supervised worker in production.

$jobId = $queue->dispatch(
    new SendWelcomeEmail($user->email, $user->name),
    queue: 'emails',
    connection: 'database',
);

// Start a worker
php green queue:work --queue=emails --connection=database
11 — EVENTS

Signals

Signals are a small synchronous event system for decoupling application behavior. Lower priority values run first; returning false stops propagation.

signal()->listen('user.created', function (array $payload) {
    // Welcome the new user.
}, priority: 0);

$results = signal()->emit('user.created', ['user' => $user]);
12 — FILES & CACHE

Storage

The Drive subsystem offers a uniform API for local, S3-compatible, and in-memory test storage. All paths pass through a security-focused validator before filesystem access.

drive()->put('avatars/42.jpg', $contents);
drive()->exists('avatars/42.jpg');
drive()->readStream('exports/report.csv');

cache()->remember('dashboard.stats', 300, fn () => $stats->build());

Architecture

A request follows a short, observable path. The application container owns shared services; subsystem managers own focused driver selection and runtime behavior.

15 — OUTBOUND HTTP

Connect

Connect handles calls to payment gateways, messaging providers, CRMs, and other external APIs. Named connections centralize base URLs, headers, and timeouts.

$response = connect()
    ->connection('payments')
    ->withToken($token)
    ->retry(3, 200)
    ->post('/charges', ['amount' => 1000, 'currency' => 'usd']);

if ($response->successful()) {
    $charge = $response->json();
}

HTTP errors do not throw automatically; call ->throw() when desired. Tests can use connect()->fake() and sent-request assertions.

16 — PERFORMANCE

Cache

The unified cache manager ships with array, file, database, and Redis drivers. Use the default store or select one explicitly.

$value = cache()->get('key');
cache()->put('key', $value, 60);
$result = cache()->remember('stats', 300, fn () => expensive_lookup());

cache()->store('redis')->put('preview', $data, 30);

Custom drivers register through CacheManager::extend() and implement CacheDriverInterface.

17 — LOCALIZATION

Translations & pluralization

JSON translations are grouped by the first key segment. Green supports interpolation, fallback locales, Twig helpers, CLDR pluralization—including Arabic’s six forms—and parsed translation caching.

t('home.welcome');
t('layout.hello', ['name' => 'Yasser']);
trans_choice('posts.comments_count', 5, ['count' => 5]);

php green translation:clear
Key resolution

auth.login.title reads lang/{locale}/auth.json at login.title. Keys without a dot use messages.json.

18 — DIAGNOSTICS

Errors, debugging & logging

The global exception handler catches exceptions, warnings, and fatal errors. Debug mode renders detailed diagnostics; production returns sanitized HTML or structured JSON based on the request.

final class PaymentService
{
    public function __construct(private readonly Logger $logger) {}

    public function process(): void
    {
        $this->logger->info('Payment started', ['user_id' => 1]);
    }
}

leaf($user); // formatted dump, then terminate

The logger supports pluggable drivers, deduplication, rate limiting, and loop prevention. Use leaf() only in development; configure its limits with published config or leaf_config().

20 — DATABASE OPERATIONS

Migrations & schema

Migrations are ordered PHP classes with reversible up() and down() methods. Green records completed files in batches and rolls the latest batch back in reverse order.

php green create:migration create_orders_table
php green migrate
php green migrate:status
php green migrate:rollback

php green migrate --dry    # Preview SQL
php green migrate --force  # Allow destructive operations
Schema::create('orders', function (Blueprint $table): void {
    $table->id();
    $table->string('reference')->unique();
    $table->decimal('total', 10, 2);
    $table->timestamps();
});
Safe by default

Destructive operations such as dropping a table require --force. Use --dry first to inspect generated SQL.
